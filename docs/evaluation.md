# 온톨로지 종합평가

이 문서는 온톨로지 제품의 종합평가 항목과 지표의 의미를 소유한다. 평가자는 현재
구현·검증·실제 사용 근거를 구분하여 판단한다. 실행·검증 방법은
[AGENTS.md](../AGENTS.md)가 소유하며, 접근·변경·복구는 호출자의 승인과 해당 소유
계약을 따른다. 이 기준을 읽는 것만으로 실험이나 운영 데이터 접근·변경을 시작하지 않는다.

## 평가 목적

궁극적인 기준은 **사용자가 허용된 지식을 정확하고 충분하게 찾아 재사용하고,
작업을 제대로 마치는 데 드는 총부담을 줄이며, 변경·장애 뒤에도 지식을 신뢰할 수
있는가**다. 저장량·관계 수·호출 수·짧은 입력만으로 목적 달성을 판단하지 않는다.

종합평가는 아래 네 항목을 모두 다루되, 확보하지 못한 근거는 미확인으로 남긴다.
임의의 가중치나 합산 점수로 결론을 대신하지 않는다. 합격선은 해당 작업의 요구와
위험을 근거로 평가 전에 정하며, 일반 백분율이나 시간 목표를 모든 작업에 강제하지 않는다.

## 보존해야 할 제품 경계

네 항목에 앞서 [저장·검토·근거](../README.md#저장검토근거)와
[관계·목적 소속 계약](graph-taxonomy.md)에 맞는지 확인한다.

- 원문·출처·identity·revision·history와 보존된 근거를 유지하고, 조회 사본의 현재성을
  구분하는가. 저장·수락 상태나 digest 일치가 사실의 정확성 판정을 대신하지 않는가.
- 승인한 store·scope·경로와 역할의 읽기·쓰기 경계를 지키는가. 접근 거절·연결 실패·
  조회 사본 미준비를 자료 부재로 오인하지 않는가.
- 문서 링크·의미 관계·근거·목적 소속의 의미가 일관되고, 수동 선택과 소속 보존을
  지키는가. 지도 거리나 같은 단어를 사실 관계로 승격하지 않는가.

이 경계의 확인된 위반은 속도나 편의 개선으로 상쇄하지 않는다. 현재 범위로 확인할 수
없으면 결함으로 단정하지 않고 해당 결론의 한계를 밝힌다. 형식적 추론·자동 진실 판정 등
제품이 제공하지 않는 기능을 이름만으로 필수 조건으로 추가하지 않는다.

## 네 평가 항목

| 항목 | 구조에서 확인할 것 | 실제 효과를 판단할 주 지표 |
| --- | --- | --- |
| 검색·재사용의 실효성 | 필요한 지식과 관계를 찾고 현재 원문·당시 근거까지 확인하는 흐름 | 대표 작업의 확인된 성공 수/평가 대상 수, 필요한 근거의 검색 충족률 |
| 검토 절차의 비용 대비 효과 | 작성·검토·검증·적용의 인계와 실패·수정 흐름 | 같은 품질 조건에서 전체 완료 시간, 관측 토큰 또는 실제 비용, 사람의 재확인·재작업 |
| 실제 운영·복구 | 설치된 실행기·앱·DB·갱신·백업이 대표 흐름으로 연결되는지 | 실제 환경의 성공·실패·미확인, 복원 내용의 동일성, 관측 복구 시간과 손실 범위 |
| 필요한 컨텍스트의 충분한 선택 | 범위와 역할에 맞게 찾고 필요한 시점에 읽으며, 중복·상한을 관리하는지 | 역할별 필수 근거 충족률과 불필요하다고 확인된 전달 본문량, 최종 작업 품질 |

**작업 성공**은 미리 정한 필수 사실·제약·완료 조건을 만족한 결과다. 원문과의 일치,
주장의 근거, 최신성·반대 근거, 모를 때의 유보를 해당 작업에 맞게 판정한다. 근거 인용의
정확성과 답의 정확성은 별도로 확인한다. 관계·소속 판단은 정확한 원문 문자열뿐 아니라
정의된 의미와 사용 목적에 맞는지도 본다.

평가 대상 수에는 사전에 선택한 적용 대상 사례를 사용한다. 대상·실행·성공·실패·취소·
미확인 수와 적용 제외 이유를 함께 남긴다. 미실행·미평가 사례는 확인된 성공에 포함하지
않으며 실패로 단정하지도 않는다. 일부 실행의 성공률을 전체 성공률로 표시하거나 실패한
사례를 사후 제외하지 않는다. 소표본은 비율과 함께 건수·사례별 결과를 제시한다.

## 필요한 컨텍스트의 충분성과 최소성

다음 연결이 갖춰졌는지와 실제 실행에서 작동했는지를 구분한다.

1. 작업·역할·허용 범위를 먼저 정하고, 제목·경로·revision 등 가벼운 조회 정보로 후보를
   좁힐 수 있는가. 조회 정보만으로 내용을 읽었거나 정책을 로드했다고 처리하지 않는가.
2. 필요한 원문·필수 정책·대상·보강 및 반대 근거를 선택하여 읽는가. 완전한 원문 읽기가
   필요한 계약은 요약·부분 발췌로 대체하지 않는가.
3. 역할별로 필요한 입력을 전달하고 같은 역할 안의 불필요한 중복을 줄이는가. 원문 변경·
   조회 상한·캐시·중단 때문에 근거가 빠지거나 오래된 입력이 쓰이지 않는가.
4. 부족한 입력을 인식하고 허용된 추가 조회 또는 미확인 보고로 이어지는가. 읽기 제한을
   지켰다는 사실만으로 충분한 입력이라고 판단하지 않는가.

검색 충족률은 **찾은 필수 근거 단위 수/필요한 근거 단위 수**다. 전달 충족률은 같은
필수 근거가 해당 역할의 입력에 충분하게 들어갔는지를 본다. 근거 단위와 충분성은
평가 전에 질문·원문·정책으로 정하고, 같은 사실을 뒷받침하는 대체 근거는 중복 요구하지
않는다. 결과에 나온 근거만으로 정답 집합을 만들지 않는다. 필요한 근거 집합을 확인할
수 없으면 충족률은 미확인이며, 발견한 누락 사례만 보고한다.
필수 근거 단위가 0개인 사례는 이 비율을 적용 제외로 두고, 사전에 정한 부재·유보 등
기대 행동으로 평가한다.

불필요한 전달 본문량은 작업·역할의 요구와 대조하여 **불필요하다고 확인한 부분의
UTF-8 바이트 수**로 본다. 판정하지 못한 부분은 별도로 남긴다. 인용되지 않은 내용도
정책 준수·탐색·반대 근거 검토에 필요할 수 있으므로 자동으로 낭비로 세지 않는다.
역할 사이에 같은 근거가 반복되는 것도 각 역할에 필요한지 확인한 뒤 판단한다.

관측은 DB에서 읽은 본문, 도구가 반환한 본문, 역할에 전달한 입력, 실행기가 보고한
입력·출력 토큰을 구분한다. 바이트 수를 토큰·금액으로 환산하지 않는다. 캐시 사용량의
포함 관계와 전체 입력을 확인하며, DB 읽기 감소를 모델 입력 감소로 해석하지 않는다.
본문량과 충족률만으로 효과를 확정하지 않고 최종 품질·전체 시간과 함께 비교한다.

## 사례 선택과 비교

평가 전에 질문, 적용 범위, 대표 사례, 기대 결과·근거, 품질 기준, 비교 대상과 종료
조건을 기존 작업·실험 기록에 정한다. 대표 사례는 사용자가 실제로 해결하려는 질문에서
고르며, 쉬운 성공 사례만으로 구성하지 않는다. 필요한 경우에 다음 유형을 포함한다.

- 정확한 표현·바꿔 쓴 표현·여러 원문의 결합으로 필요한 지식을 찾는 작업.
- 정정·철회·원문 변경 뒤 현재 사실과 과거 근거를 구별하는 작업.
- 자료가 없거나 근거가 충돌할 때 유보하고, 거절·미준비·실패를 부재와 구별하는 작업.
- 허용 범위 밖 요청, 긴 입력·반환 상한, 중단·재개·복원 등 해당 위험을 다루는 작업.

일반 평가마다 모든 유형이나 새 벤치마크를 실행하지 않는다. 기존 사례·관측·실패 근거를
재사용하고, 결론을 바꿀 공백에만 필요한 검증을 추가한다. 합성 자료의 결과와 허용된 실제
사용 자료의 결과는 구분하며, 실제 자료가 필요해도 평가 기준이 접근 범위를 넓히지 않는다.

효과 비교는 같은 요청·원문 revision·품질 기준과 비교 가능한 실행 조건에서 한다.
변경 요소, 실행기·모델·설정·캐시 조건, 순서·표본 차이를 밝힌다. 품질을 충족한 사례의
비용을 비교하되, 양쪽의 실패·미확인과 비교 제외를 함께 제시하여 성공 사례만 남기는
편향을 드러낸다. 기준선이 없으면 구조 개선과 관측 결과까지만 말하며 절감 효과는 미확인이다.

전체 완료 시간은 요청 시작부터 필요한 검색·작성·검토·수정·검증·적용이 끝날 때까지의
관측 시간을 사용한다. 실패·재시도·준비 비용과 평가 자체의 비용도 포함 범위를 밝힌다.
전체 경과 시간과 구성 단계 시간, 사람의 작업 시간은 구별하며 병렬 역할·대기를 중복 합산하지
않는다. 사용량·금액을 확인하지 못한 경우 0으로 채우지 않는다. 모델 평가는 보조 근거로
쓰고 실제 오류·사람의 수정과 대조한다.

## 실제 운영과 복구의 확인 범위

소스 구조, 합성 테스트, 설치된 실행기의 실제 동작, 사용자의 결과를 각각 구분한다.
CLI의 한 요청, 화면 검증 페이지 또는 백업 파일 생성의 성공을 전체 운영 성공으로
확대하지 않는다. 대표 요청이 조회·화면·저장·갱신 등 필요한 단계와 실패 대응을 거쳐
완료되는지 확인하며, 사용자가 직접 찾고 이해하고 수정할 수 있는지도 함께 본다.
설치·로컬 반복·진단·유지보수의 부담이 다른 단계로 옮겨졌는지도 평가한다.

복구는 [기존 백업·복원 계약](../AGENTS.md#백업과-복원-확인)에 따라 별도의 빈 DB에서
확인한다. 원문·첨부·identity·revision·history·기억·근거와 해당 실행에 필요한 복구 상태의
내용 보존, 필요한 조회 사본의 재생성, 대표 작업의 재개를 구분하여 확인한다. 건수·digest·
백업 존재만으로 내용 복원을 대신하지 않는다. 복구에 걸린 시간과 마지막으로 보존된
시점 이후의 손실 범위를 관측하고, 허용 복구 시간·손실 목표는 사용 필요에 따라 별도로
정한다. 복원이나 장애 시험을 하지 않았다면 복구 가능성의 실측은 미확인이다.

실행·복원·변경 검증은 기존 승인과 실행 계약 안에서 수행한다. 읽기 전용 평가의 완료에
운영 중단이나 실험 실행을 기본으로 추가하지 않는다.

## 결과와 재평가

결과에는 다음 내용을 기존 작업 기록이나 보고에 남긴다. 별도 평가 DB·원장·상시 수집기를
만들지 않으며, 이 문서에 실행별 결과나 비공개 원문을 누적하지 않는다.

- 평가한 commit·변경, 기준 적용 시점, 대상 환경·설정과 확인 시각, 읽고 실행한 범위.
- 네 항목별 구조 관측과 실제 효과, 지표의 정의·단위·분모·출처·관측 범위.
- 확인된 강점·요구 위반·미확인·선택적 개선, 대상·실행·성공·실패·취소·제외의 건수.
- 사용자 결과에 큰 영향을 주는 다음 확인·수정과 해소 조건. 담당·기한은 확인된 것만 쓴다.

전체 준비나 효과를 좌우하는 미확인이 있으면 전체 완료·효과를 확정하지 않는다. 새 변경,
새 실패 또는 원문·정책·환경 변경이 판단에 영향을 줄 때 관련 항목만 재평가한다.
지표·기준을 바꿀 때는 근거와 적용 시점을 남기고 이전 결과·기준을 보존하며, 진행 중
비교나 과거 결과에 새 기준을 소급하여 유리한 결론을 만들지 않는다.

## 기존 구현과 연구의 활용

실행과 관측은 기존 [하네스 비교 실험](../AGENTS.md#하네스-비교-실험),
[개발 검증](../AGENTS.md#개발-검증), [백업·복원](../AGENTS.md#백업과-복원-확인)을
필요할 때 재사용한다. 입력 관측은 [native role](../src/native_role.rs), source 조회는
[native context](../src/native_context.rs), 역할별 입력 구성은
[Core Harness](../crates/context-core/src/harness.rs)가 소유한다. 현재 관측이 위 지표를
자동으로 모두 계산한다고 가정하지 않으며, 필요한 판단을 할 수 없을 때만 최소한으로 보완한다.

다음 자료에서 평가 질문을 참고했다. 위 기준은 이 제품에 맞춘 선택이며 외부 표준의
인증·벤치마크 통과를 뜻하지 않는다.

| [TOVE의 온톨로지 방법론](https://eil.mie.utoronto.ca/theory/enterprise-modelling/entmethod/) | 지원해야 할 실제 질문에서 범위와 평가를 시작한다. 이 제품에 일차 논리 모델을 요구하는 근거로 쓰지 않는다. |
| [RAGAs](https://aclanthology.org/2024.eacl-demo.16/) · [ALCE](https://aclanthology.org/2023.emnlp-main.398/) | 검색 맥락·답·근거 인용의 품질을 구분한다. 모델 판정이나 해당 논문의 성능을 이 제품의 정확성으로 대신하지 않는다. |
| [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) | 필요한 시점의 조회와 작고 충분한 입력을 검토한다. 조회를 잘게 나누는 비용도 함께 본다. |
